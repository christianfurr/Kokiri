# Human mod launch source review

The launcher builds a private copied overlay with a random launch token, a hash-pinned handoff and a manifest bound to the human session and executable. Its helper uses clean arguments/environment. Native independently validates the handoff and files, retains the overlay directory descriptor, and uses no-follow relative reads. Private payload and manifest identity checks include ctime across hashing, parsing, opening and reads. Historical inert snapshots do not consume the current profile audit budget; only the requested snapshot is fully inspected.

`KokiriHumanPreviewModsVersion=1` is emitted only for a newly source-compiled, receipt/hash-matched human package. Generic or shader-only repackaging cannot stamp it. The ordinary capability remains distinct. Existing private runtimes stay unmodded; an enabled profile fails visibly if the new capability is absent.

Bounded preparation requires actual cached native request validation and exact prior payload inventory/hashes. Its three generated list/key files are regenerated by the normal verified publisher. Library validation freshly observes compiler identity and hashes every existing library/current source, refuses incomplete/context-drift/corrupt inputs and refuses code generation. Archive-only packaging invokes fresh full strict verification before writing a new preparation receipt.

Verification on the source candidate:

- 65 Swift tests passed under the two-worker CPU grant, including actual launcher-target compilation and synthetic private manifests. The slot was released.
- 16 mocked clean-helper tests and 16 single-file native isolation tests passed, including tampered payloads, stale session identity, symlinks/hardlinks, restored-mtime edits after open, history bounds and unchanged human control restrictions.
- Focused seed, resume, library and packaging regressions cover missing/changed inventories, corrupt outputs, compiler drift, cached-only refusal and propagation of archive verification failure before receipt publication.
- Actual `romfs.c` passed clang syntax validation with warnings treated as errors. This produced no native runtime.
- Independent focused source review found no remaining P1/P2 issues after fixing file/manifest mutation, historical snapshot audit growth and generated-seed inventory handling.

Limits: no new runtime, Metal verification, modded gameplay, installation or release is accepted by these source checks. Integration owns the exclusive native build and later separate copied-profile acceptance. The current installation, working game, player data, caches and foreign/own mod libraries were not modified by this source task. Historical snapshots are retained as inert evidence; no potentially live snapshot is deleted.
